# UI Design

## Design Direction

The interface uses an operational, finance-workspace style rather than a marketing-style landing page. The goal is for employees and approvers to scan claim details, totals, statuses, and comments quickly.

### Color Scheme

- **Primary green:** `#183f2b` for primary commands and branded emphasis.
- **Action green:** `#26734d` for active navigation and interactive emphasis.
- **Canvas:** `#f3f5f2` for the application background.
- **Surfaces:** White for claim lists, editors, details, and audit panels.
- **Neutral text:** Stone shades for readable primary and secondary content.
- **Semantic colors:** Blue for submitted, emerald for approved, red for rejected, violet for paid, and stone for draft.

### Typography

- **Interface/body:** DM Sans for form labels, tables, comments, and general content.
- **Headings and totals:** Manrope for concise workspace titles and monetary values.
- Text remains restrained in the compact operational interface, with clear weight differences instead of oversized display type.

### Layout

- Persistent role-switcher header with the active role and signed-in demonstration user.
- Secondary Claims and Audit Trail navigation.
- Employee workflow uses a wide editor and a narrower draft/history sidebar.
- Manager and Finance workflows use a claim queue beside an expanded review panel.
- Audit trail uses a claim list beside a vertical timeline.
- Desktop layouts use restrained borders and full-width work areas. Narrow screens retain scrollable line-item grids and readable stacked controls.

## Design Prompts Used

1. "Create a professional expense approval workspace that feels operational, restrained, and easy for repeated daily use."
2. "Use a role switcher for Employee, Manager, and Finance without changing the overall application structure."
3. "Keep claims, totals, statuses, comments, and audit events visible without oversized marketing sections or decorative cards."
4. "Design claim approval screens around a queue on the left and claim details plus decision controls on the right."
5. "Use Tailwind, familiar icons, compact borders, clear status colors, and responsive tables."

## Claim View Iteration

### Before

The initial claim view was treated as a single tall form-like screen. The employee draft, submitted claim history, approver decision controls, line items, and audit details competed for the same vertical space. It was difficult for approvers to compare queue items with the selected claim and totals were easy to miss.

### After

The claim view was split by responsibility:

- A queue panel lists claims that need the active role's attention.
- The selected claim appears in a wider detail panel with its line items and total.
- Approver comments and actions remain directly below the claim information.
- Status badges use consistent semantic colors.
- Approved finance claims expose a dedicated **Mark as Paid** action.
- The audit trail receives a separate claim selector and vertical timeline.

### Design Decisions Retained

- Borders define work surfaces rather than nested decorative cards.
- The selected claim uses a green left edge to establish current context.
- Monetary totals use a stronger display weight and right alignment.
- Comments appear in an unadorned text area so approvers can focus on the decision.
- Audit entries display actor, action, timestamp, status transition, and comment without relying only on icons.

## Design Iteration (Before & After Critique)
- **First AI Output:** The initial layout generated by the AI agent had basic HTML tables with no status badges, poor mobile responsiveness, and crowded form fields for line items.
- **Critique & Prompt Iteration:** I instructed the AI: *"Refactor the UI using Tailwind CSS to include distinct status badges (Draft, Submitted, Approved, Rejected, Paid), clean cards for line items, and a responsive top-navigation role switcher."*
- **Final Result:** The refined interface features clear visual hierarchy, distinct color-coded badges, and a professional workspace layout matching the final screenshots.
